# BeeFintech 官网改造 SPEC 需求文档

## 1. 项目背景

本项目服务于 Vibe Coding 实战成长赛，目标是将 BeeFintech 官网从“静态宣传册”升级为“可交付的保险科技 Web 服务平台”。项目需要同时证明三件事：业务表达更清晰、预约演示流程可在线承接、官网具备持续扩展增值服务的能力。

当前仓库 `officialWebsite` 已采用单仓结构，包含 `apps/web` 前端门户、`apps/api` 后端 API、`docs` 比赛文档和 `infra` 本地基础设施。

## 2. 业务目标

- 对外清晰展示 BeeFintech 的保险科技服务能力、解决方案和可信度。
- 支持潜在客户在线提交预约演示，并由后端 API 承接数据。
- 至少落地 1 个增值服务功能，体现官网从展示型页面向服务型平台升级。
- 将 AI 协作、需求拆解、开发过程、测试过程和复盘沉淀为可复用资产。

## 3. 用户角色

| 用户角色 | 核心诉求 | 典型行为 |
| --- | --- | --- |
| 潜在客户 | 快速理解 BeeFintech 能解决什么问题 | 浏览首页、方案页、服务页，提交预约演示 |
| 业务/销售同学 | 获取客户线索并跟进 | 登录后台，查看预约演示列表 |
| 运营/流程同学 | 维护内容和服务模块 | 梳理 FAQ、术语、更新日志和政策内容 |
| 开发同学 | 快速扩展官网服务能力 | 接 API、补测试、维护模块注册表 |
| 评审/管理者 | 判断作品是否可交付、可复用 | 查看 GitHub、文档、演示路径和测试记录 |

## 4. 功能范围

### 4.1 P0 必交功能

- 品牌宣传门户：首页、解决方案页、关于页、服务模块页。
- 预约演示入口：前端表单收集姓名、公司、联系方式、需求描述等信息。
- 预约演示 API：后端提供公开接口，完成基础校验、入库和后续外部 API 编排预留。
- 最小后台：管理员登录后可查看预约演示列表和服务模块列表。
- GitHub 交付：代码、文档统一托管；成员均需有独立 Commit 记录。
- 标准文档：需求文档、执行规划文档、AI 协作记录、测试说明、复盘总结。

### 4.2 P1 增值服务主线

本组首选实现“工具服务类”增值能力：保险科技 ROI 计算器，并联动术语词典作为解释辅助。

ROI 计算器目标：

- 支持用户输入保单处理量、人力成本、自动化比例、客单价值等参数。
- 输出预估节省成本、效率提升、投资回收周期等结果。
- 提供计算口径说明，避免把估算结果包装成财务承诺。
- 前端具备可演示页面，后端预留或提供计算 API。

术语词典目标：

- 收录保险科技常见术语，如核保、理赔自动化、OCR、RPA、风控模型、渠道转化等。
- 在 ROI 计算器或服务页中提供解释入口，降低非技术用户理解成本。

### 4.3 P2 可扩展服务

- 内容服务类：保险科技资讯、政策解读专栏。
- 客户赋能类：FAQ 自助查询、在线工单、更新日志发布。
- 后台能力：内容发布流、模块启停、角色权限。

P2 功能不是首轮比赛交付的必成项，但需要保留路由、模块注册和文档说明，证明系统具备扩展能力。

## 5. 核心业务流程

### 5.1 预约演示流程

1. 潜在客户进入官网，浏览解决方案和服务能力。
2. 用户进入预约演示页，填写表单并提交。
3. 前端调用 `POST /api/public/demo-requests`。
4. 后端校验请求参数，保存预约记录。
5. 业务/销售同学登录后台查看预约列表。
6. 后续可在 `DemoIntegrationGateway` 中接入 CRM、企微、钉钉或真实预约系统。

### 5.2 ROI 计算器流程

1. 用户进入工具服务页，选择 ROI 计算器。
2. 用户填写业务量、人力投入、自动化预期等参数。
3. 系统返回估算结果和计算说明。
4. 用户可基于结果提交预约演示，形成“工具体验 -> 销售线索”的转化闭环。

## 6. 非功能需求

- 可演示性：本地启动后可以完成首页浏览、预约提交、后台查看和 ROI 计算演示。
- 可维护性：前后端目录清晰，模块边界明确，文档与代码同步更新。
- 可测试性：关键 API 和模块注册逻辑需要有自动化测试或可复现验证记录。
- 安全性：后台接口需要基础认证；默认账号密码仅用于本地演示，生产化前必须改造。
- 可扩展性：增值服务通过模块注册表统一管理，避免后续新增功能时大改路由结构。

## 7. 验收标准

| 验收项 | 标准 |
| --- | --- |
| 品牌官网 | 首页、解决方案、关于、服务页面可访问，核心文案完整 |
| 预约演示 | 前端可提交，后端 API 可保存，后台可查看 |
| 增值服务 | 至少 ROI 计算器可演示，最好联动术语词典 |
| 后台 | 管理员可登录，可查看预约和服务模块 |
| 文档 | 5 份比赛文档齐全，且能体现 AI 协作过程 |
| GitHub | 至少 2 个分支，每位成员有独立 Commit |
| 测试 | 前端构建、后端测试、关键手工联调记录齐全 |

## 8. 本期不做

- 不做完整生产级 RBAC 权限系统。
- 不做复杂 CMS 审核流。
- 不承诺三类增值服务全部完整上线。
- 不做真实线上支付、真实投保、真实客户数据处理。
- 不把 ROI 结果作为正式财务承诺，仅作为销售前咨询估算工具。
