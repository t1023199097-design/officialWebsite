# LifeBee 官方网站 SPEC 需求文档

## 1. 项目目标

建立 Beefintech 旗下 LifeBee 品牌官方网站，面向香港保险经纪公司、合作伙伴与潜在企业客户，展示 LifeBee 作为一站式数字化业务流程辅助工具的品牌定位、产品能力和服务价值。

网站需要在短时间内让访客理解：

- Beefintech / LifeBee 是谁。
- LifeBee 能解决香港保险经纪行业哪些核心痛点。
- LifeBee 如何通过 APP、Admin、AI Robot、保险公司 API 授权、私有化部署与数据隔离提升运营效率。
- 为什么 LifeBee 值得预约演示、进一步沟通或合作。

第一版以品牌展示、产品能力说明和商务转化为主，不包含完整 CMS、会员系统、支付系统或复杂后台运营功能。

## 2. 目标用户

- 香港保险经纪公司管理层：关注效率、安全、数据主权、团队管理和业务增长。
- 外部理财顾问与保险业务团队：关注客户、保单、文件、新单、续保和介绍费流程是否更清晰。
- 企业合作伙伴：关注系统能力、API 接入、私有化部署和长期扩展性。
- 投资人或行业观察者：关注 Beefintech / LifeBee 的产品成熟度、客户体量与金融科技能力。

## 3. 品牌定位

LifeBee 是面向香港保险经纪场景的一站式数字化流程辅助工具，帮助保险经纪团队将客户、保单、文件、任务、提醒、介绍费与运营数据统一到可控工作流中。

品牌表达关键词：

- 专业可信
- 科技金融
- 高效便捷
- 数据安全
- 信息隔离
- 企业级控制力
- 客户至上

## 5. 页面范围

### 5.1 首页

首页作为第一屏品牌展示和转化入口，需包含：

- 品牌导航与语言切换。
- Hero Slogan 与产品价值说明。
- 科技金融蓝不规则球形动态视觉。
- LifeBee 产品工作台示意。
- 信任背书与核心运营数据。
- 工具与服务功能滑动展示。
- 解决方案矩阵。
- 预约演示 CTA。

### 5.2 解决方案页

展示 LifeBee 对香港保险经纪业务流程的整体支持：

- 新单业务管线。
- 既有保单服务。
- 续保与跟进。
- 团队交接。
- 数据安全。
- 管理报表。
- 保险公司 API 授权。
- 私有化部署与权限隔离。

### 5.3 案例与成果页

以匿名化或演示数据展示平台成果：

- 已投入使用用户量。
- 已服务客户资料量。
- 已处理流程个案。
- 平均运营效率提升。
- 改造前后对比：分散表格与聊天工具 vs 统一流程与可控数据访问。

### 5.4 关于我们页

展示 Beefintech / LifeBee 的公司背景、愿景与产品理念：

- 金融科技能力。
- 香港保险经纪场景适配。
- 长期合作导向。
- 安全、效率、清晰、伙伴关系等核心原则。

### 5.5 联系我们 / 预约演示页

用于收集潜在客户线索：

- 姓名。
- 公司。
- 电邮。
- 电话。
- 感兴趣范围。
- 需求描述。

第一版表单可先以前端展示或连接现有预约 API 为主，后续再接入正式 CRM、邮件通知或第三方预约系统。

### 5.6 404 页面

提供友好提示与返回首页、联系 LifeBee 的入口。

## 6. 视觉设计语言

### 6.1 色彩体系

主色系为科技金融蓝：

- 深墨蓝：用于标题、重要正文和企业级可信感。
- 高饱和金融蓝：用于 CTA、重点数据、导航激活态。
- 亮青色：用于动效高光、状态反馈、图表点缀。
- 紫蓝渐变：用于科技感球形视觉和空间层次。
- 浅蓝白背景：用于保持页面明亮、专业和可读。

整体避免过度营销化的装饰，保持金融科技企业网站应有的克制、可信和扫描效率。

### 6.2 排版

- 首页主标题使用大字号、强对比、短句断行。
- 「客戶至上，服務為先」作为主视觉焦点。
- 「以科技力量擁抱世界」作为副标题，换行展示并缩小一级。
- 内容模块标题保持清晰、有业务含义，避免空泛口号。
- 卡片内标题不使用过大的 hero 字级，保持信息密度。

### 6.3 组件风格

- 按钮使用圆角胶囊形，主按钮采用蓝紫渐变。
- 卡片圆角控制在 8px 左右，符合专业后台与 SaaS 工具气质。
- 数据卡片保持清晰分隔，便于快速扫描。
- 工作台示意图采用半透明玻璃质感，但不使用过度拟物装饰。

## 7. 动效需求

### 7.1 首页不规则球形动效

首页右侧或背景需包含不规则球形渐变动效，用于传达科技金融感。

动效要求：

- 默认持续缓慢变形与位移。
- 动效速率较第一版更快，建议主动画周期约 4.2 秒。
- 鼠标悬停在 Hero 视觉区域时，球形动效进一步加速，建议约 2.4 秒。
- Hover 时增加亮度、饱和度、青色光晕和轻微浮动。
- 需要支持 `prefers-reduced-motion`，降低系统关闭动效用户的不适。

### 7.2 产品工作台示意交互

工作台卡片在 Hero 区域与球形视觉共同展示：

- 默认作为视觉说明，不提供真实点击功能。
- Hover 时可轻微上浮并增强阴影。
- 内部状态条和图表可使用轻微脉冲动画，体现实时运营状态。

### 7.3 工具与服务功能滑动展示

参考 Stripe 网站中横向滑动展示的处理方式，首页需展示以下功能：

- 資訊
- 產品庫
- 投保
- 新單
- 保單
- 介紹費

交互要求：

- 仅作为滑动展示，不需要点击跳转。
- 横向自动循环滑动。
- 鼠标悬停在滑动区域时可暂停滑动。
- 鼠标悬停在单个功能卡片时，触发轻微波动光效。
- 色系需与当前首页科技金融蓝保持一致。

## 8. 多语言需求

网站需支持三种语言版本：

- 繁体中文：默认语言。
- 简体中文。
- 英文。

语言切换要求：

- 顶部导航提供「繁 / 简 / EN」切换控件。
- 切换后导航、首页、解决方案、案例、关于、联系、表单和 404 页面文案同步变化。
- 第一版可采用前端状态切换，不强制要求独立 URL。
- 后续正式版本可扩展为 `/zh-hant`、`/zh-hans`、`/en` 路由，以支持 SEO。

## 9. 功能模块内容

### 9.1 資訊

集中展示市场资讯、产品更新与团队公告，减少跨群组查找。

### 9.2 產品庫

按保险公司、产品类型与销售场景整理产品资料，帮助顾问快速取得准确内容。

### 9.3 投保

承接投保资料、文件与节点提醒，让行政与顾问保持同一进度。

### 9.4 新單

把新单从线索、客户到文件补交整理成可追踪的流程管线。

### 9.5 保單

集中保单状态、文件与服务记录，支持续保和客户服务跟进。

### 9.6 介紹費

清晰记录介绍费状态、归属与核对进度，降低人工对账成本。

## 10. 数据与信任背书

首页需展示以下演示级数据，后续可替换为真实数据：

- `1,200+`：已投入使用的活跃用户。
- `80,000+`：已服务客户资料量。
- `300,000+`：已处理流程个案。
- `35%`：平均运营效率提升。

信任背书标签：

- 经纪运营。
- 顾问 APP。
- 管理后台。
- 保司 API。
- 数据金库。

## 11. 技术实现要求

### 11.1 当前官方项目落地方式

在 `officialWebsite` 项目中，第一版应作为演示初稿放入 `apps/web` 前端：

- 使用现有 Next.js 项目结构。
- 保留 Spring Boot 后端与已有预约 API。
- 将 LifeBee 首页视觉语言、动效和内容作为新的官网演示首页。
- 不破坏现有后台、预约、模块注册等后端能力。

### 11.2 内容管理

第一版可使用前端静态内容数据：

- 便于快速替换文案。
- 便于后续接 CMS 或后台内容发布能力。
- 多语言内容应集中管理，避免散落在页面组件中。

### 11.3 响应式

需适配：

- 桌面端宽屏。
- 常规笔记本。
- 平板。
- 手机端。

移动端要求：

- 主 Slogan 不应溢出。
- CTA 按钮不应挤压或遮挡。
- 产品工作台示意图可缩小或纵向排列。
- 功能滑动卡片需保持可读。

## 12. 验收标准

第一版验收需满足：

- 首页能清晰展示 LifeBee 品牌主张。
- 主 Slogan 与副 Slogan 按设计层级展示。
- 首页不规则球形动效正常运行，hover 有视觉反馈。
- 工具与服务功能滑动展示正常运行。
- 功能卡片 hover 有轻微波动光效。
- 页面默认中文内容完整，无明显英文残留，英文仅出现在英文版本。
- 支持繁体中文、简体中文、英文切换。
- 预约演示入口可访问。
- 页面在桌面和移动端无明显文字重叠、截断或布局错位。
- 前端构建通过。
- 现有模块目录测试通过。

## 13. 后续扩展

后续版本可继续扩展：

- 接入正式预约 API 或 CRM。
- 增加真实客户案例与 Logo 墙。
- 增加内容中心或资讯专栏。
- 增加产品库详情页。
- 将多语言切换升级为 SEO 友好的独立路由。
- 接入后台 CMS。
- 增加图表化运营数据展示。
- 增加隐私政策、服务条款与合规说明。
