## 时刻 4：官網 Spec V2.0 參賽提交版整理

任务：
根据团队最新讨论，将 Beefintech -- Lifebee 官网需求文档调整为正式参赛提交版。官网定位从产品功能说明收敛为品牌推广、潜在客户吸引、市场成果展示和预约咨询转化。

AI 给的初稿：
AI 以产品经理和技术文档工程师角色重新整理文档结构，输出标准 Spec 格式，包含文件信息、版本记录、项目背景、项目目标、官网定位、目标用户、核心价值主张、需求范围、视觉设计要求、页面清单、页面需求、基础功能、适配要求、交付范围和验收标准。

我们改了什么：
1. 首页信息架构调整为品牌功能介绍、市场业务规模、预约咨询演示、关于我们四个维度。
2. 品牌功能介绍只保留大模块表达，不继续罗列平台小功能和操作说明。
3. 增值服务范围只保留内容服务类，即保险科技资讯和行业政策解读专栏。
4. 删除客户赋能类和工具服务类方向，包括 FAQ、自助查询、在线工单、更新日志、ROI 计算器、行业术语词典等内容。
5. 同步生成项目内归档文档 `docs/official-website-requirements-v2.0.md`。

原因：
官网第一阶段的核心任务是让潜在客户快速理解 LifeBee 的品牌价值、服务成果和预约路径，不适合写成平台操作手册或功能清单。收敛后的 Spec 更适合作为参赛材料、设计执行依据和后续开发验收依据。

## 时刻 5：Execution document 执行计划整理

任务：
根据桌面版执行文档，将原本从视觉设计、页面需求、基础功能、适配要求、验收标准延伸出来的内容整理为可提交的 Execution document，并补齐 M4 要求的 marker、至少 4 个 Phase 和任务清单。

AI 给的初稿：
AI 先读取 `执行文档.md` 与仓库内 `docs/plan.md`，确认比赛模板要求是 `generated-by: superpowers-writing-plans` marker、Phase 结构和 checkbox 任务清单。随后在不破坏原文档格式的前提下，将文档序号从 1 开始重排，并在末尾补充实施计划。

我们改了什么：
1. 在执行文档顶部加入 `<!-- generated-by: superpowers-writing-plans -->` marker。
2. 将章节序号从 1 开始重新排列，保持原有「章节 + 小节 + 表格 + 编号清单」格式。
3. 增加 `实施计划` 章节，拆分为首页骨架与品牌视觉、核心页面内容建设、预约咨询演示与 API、适配验收与提交 4 个 Phase。
4. 每个 Phase 均使用 checkbox 任务清单，便于后续开发和验收逐项推进。
5. 将最终文件以英文名称保存为 `docs/Execution document.md`，便于仓库提交和团队识别。

原因：
Execution document 的用途是把需求文档转化为可以执行和验收的阶段任务。保留原有格式能避免文档结构被打散；补齐 marker、Phase 和任务清单则能满足比赛 M4 文档要求，并让后续开发团队更容易按阶段推进。

## 时刻 9：首页下滑导航、翻转卡片与功能服务视觉迭代

任务：
在不改动首页首屏设计、不影响右侧水滴球体的前提下，把顶部导航与首页下滑内容建立对应关系，并在首页下滑第一部分加入更有产品感的功能服务视觉展示。

AI 给的初稿：
AI 先根据用户截图理解导航栏需要作为首页内部定位入口，而不是重做首屏。最初 AI 做了导航定位效果图，随后根据反馈收敛范围：首屏当前显示内容完全不动，只处理首屏之后的展示内容。AI 先把导航改成首页锚点，再把下滑内容从普通区块调整为翻转卡片，并逐步根据用户反馈优化卡片尺寸、排列方式、间距和产品视觉。

我们改了什么：
1. 将顶部导航改为首页内锚点，对应 `品牌功能`、`市场规模`、`内容服务`、`关于我们`、`联系我们` 五个下滑模块。
2. 删除首页首屏下方原本的能力背书横栏，即 `经纪营运 / 顾问 APP / 管理后台 / 保司 API / 数据金库`。
3. 保留翻转卡片交互效果，但把五张卡片从横向聚集改为纵向逐一排列展示。
4. 每个翻转卡片下方都紧跟对应模块的信息说明，包括品牌功能、市场规模、内容服务、关于我们、联系我们的具体展示内容。
5. 根据反馈删除翻转卡片上的数字标注，让卡片更干净。
6. 收紧首屏与下滑第一部分之间的空隙，让页面衔接更紧凑。
7. 在首页下滑第一部分新增 `功能服务` 视觉段，使用 CSS 绘制 PC 管理台 + 手机功能菜单的产品示意。
8. 为功能服务视觉增加由暗到亮的屏幕内扫光动画，同时移除背景移动灰色框，避免视觉干扰。
9. 将产品视觉外框从普通设备示意调整为台式电脑显示器，并加入显示器边框、底座、内屏凹槽、手机边框、听筒和玻璃高光等质感细节。
10. 扩展 `site-content.mjs` 中的首页锚点、翻转模块和功能服务视觉数据，并在 `module-catalog.test.js` 中增加基础断言。

原因：
用户希望首页首屏已经确认的视觉保持稳定，只让下滑内容更清楚地承接导航栏。翻转卡片适合作为模块入口，但如果全部挤在一起会降低阅读节奏，因此最终改为纵向逐段叙事。功能服务视觉用于在进入卡片之前先给访客一个产品能力的直观印象；设备外框和屏幕扫光则增强科技产品质感，同时不破坏原有科技金融蓝视觉体系。

验证：
AI 每轮关键调整后都执行 `npm run test --workspace apps/web`，确认内容数据断言通过；执行 `npm run build --workspace apps/web`，确认 Next.js 生产构建成功；重启 `http://127.0.0.1:5173/` 预览服务后，检查首页与 `/#brand-functions` 锚点返回 200。

用户要求把对话里这版首页“整个页面”恢复到截图对应状态，而不是只恢复 Hero 按钮。随后又反馈网页打不开，希望先把本地预览重新拉起来并确认可访问。

AI 先核对当前仓库状态，确认首页页面代码、样式、站点数据和测试文件都还保留着截图那一版的结构。随后 AI 选择只回退后来被误恢复成两按钮状态的局部改动，把 Hero 区重新调回三个按钮版本，并保留首页首屏、右侧水滴球体、下滑功能服务视觉和后续展示模块。页面打不开时，AI 进一步重启 5173 开发服务，直接用浏览器重新打开首页做可访问性验证。

6. 把这次协作过程补写进 `docs/ai-collab-log.md`，让项目协作记录与实际操作同步。

原因：
用户这次要恢复的不是单个按钮，而是当时整版首页的状态；而“网页已打不开”又说明需要同时处理本地预览恢复。把这次过程写进协作记录，可以让后续进入 `xiaoxiao` 分支的人知道：这版首页是经过多轮确认、恢复、验证后定下来的，不是随手拼出来的临时态。

验证：
AI 重新运行 `npm run test --workspace apps/web` 与 `npm run build --workspace apps/web`，确认测试和生产构建都通过；随后重启本地开发服务并用浏览器再次打开 `http://127.0.0.1:5173/`，确认首页可访问，标题正常，Hero 区按钮数量和文案都符合截图对应版本。

## 时刻 11：产品服务页衔接旧版水滴首页与电脑展示

任务：
用户希望 `/product-services` 页面不要从 PDF 风格的功能服务页直接开始，而是先恢复之前确认过的首页首屏和第二屏：首屏包含右侧水滴特效、模块流动展示和品牌主张；第二屏包含 PC 管理台与手机功能面板。PDF 参考只用于后续产品服务功能介绍部分，不应覆盖旧版首页视觉。

AI 给的初稿：
AI 先从 Git 历史中查找旧版首页代码，定位到包含 `waterdrop-field`、`hero-module-stage`、`feature-laptop`、`feature-phone` 的页面结构和样式。随后 AI 判断用户一直查看的是 `/product-services`，而不是 `/` 首页，因此仅恢复首页本身并不能解决用户看到的问题。正确方案是将旧版首页的前两屏作为 `/product-services` 的开头，再把现有产品服务内容接在后面。

我们改了什么：
1. 在 `apps/web/app/product-services/page.js` 引入 `getDemoHomeContent`、`homeFeaturePreview` 和 `normalizeLocale`，复用旧首页的数据源。
2. 将旧版水滴首屏结构接入 `/product-services`，包括品牌文案、预约演示入口、查看功能服务锚点、右侧水滴元素和横向模块流动展示。
3. 将旧版第二屏的功能服务视觉接入 `/product-services`，包括 PC 管理台、数据卡片、柱状图、环形图、手机功能菜单和扫光装饰。
4. 保留后续 `產品功能服務升級`、香港市场、会员功能、营运基础设施、每月产值和 AI 代理服务等 PDF 衔接内容，让页面形成“旧版首页视觉 → 产品展示第二屏 → 功能服务长页面”的连续结构。
5. 在 `apps/web/app/globals.css` 增加少量衔接样式，控制前两屏与后续产品服务区块的间距，并收紧后续功能服务页面字号和卡片密度。
6. 排查用户反馈“网页打不开”的原因，确认不是页面代码缺失，而是 Next.js dev 服务的 `.next` 缓存损坏，报错为 `Cannot find module './662.js'`。
7. 停止旧的 `next dev` 进程，清理 `.next` 缓存，重新以 `npm run dev -- --port 5173` 启动本地服务。

原因：
